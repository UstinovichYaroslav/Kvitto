## Ключевые запросы к ассистенту

### 1. Создание системы платежей по ТЗ
**Контекст:** ТЗ с описанием предметной области (тарифы, промокоды, рассрочка, статусы платежей), эндпоинтов API, требований к хранению данных (копейки, int, без float/Decimal).

**Запрос:** Создать FastAPI приложение с SQLAlchemy, Pydantic v2, поддержкой SQLite/PostgreSQL, реализовать все эндпоинты согласно ТЗ.

**Результат:** Создана полная архитектура с моделями, репозиториями, сервисами, API роутами. Инициализация тарифов при старте, расчёт скидок и графика рассрочки, валидация переходов статусов.

### 2. Рефакторинг архитектуры
**Контекст:** Код с ручками, содержащими бизнес-логику (60+ строк в create_payment).

**Запрос:** Перенести файлы в api_v1, создать dependencies.py с Annotated/Depends, сделать ручки минимальными, всю логику в сервисы.

**Результат:** Создана чистая архитектура с dependency injection, ручки стали 5-10 строк, логика централизована в сервисах.

### 3. Исправление паттернов кода
**Контекст:** Репозитории с множеством аргументов в методах create.

**Запрос:** Вместо кучи аргументов получать схему (PaymentCreate), использовать model_dump() вместо прямого присваивания, добавлять переменную stmt для запросов.

**Результат:** Репозитории стали чище, методы принимают схемы, используется model_dump(), запросы через stmt.

## Ошибки модели и слабые решения

### 1. Логика в ручках вместо сервисов
**Проблема:** Изначально разместил всю бизнес-логику (валидация промокода, расчёт скидки, график рассрочки) прямо в API ручках. Это привело к функциям на 60+ строк.

**Как заметил:** Пользователь указал, что ручки должны быть максимально маленькими, вся логика в сервисах.

**Исправление:** Пернёс логику в методы сервисов (`create_payment_with_validation`, `process_webhook`), ручки стали минимальными.

### 2. Отсутствие dependency injection
**Проблема:** Ручки напрямую создавали сервисы через `PaymentService(session)`.

**Как заметил:** Пользователь попросил создать dependencies.py с функциями для возврата сервисов через Annotated/Depends.

**Исправление:** Создал dependencies.py с функциями `payment_service`, `tariff_service` используя `Annotated[AsyncSession, Depends(...)]`.

### 3. Неправильная структура репозиториев
**Проблема:** Методы create принимали множество отдельных аргументов вместо схемы.

**Как заметил:** Пользователь указал, что нужно получать схему и использовать model_dump().

**Исправление:** Создал схемы PaymentCreate/TariffCreate, методы репозиториев теперь принимают схемы и используют `Model(**data.model_dump())`.
